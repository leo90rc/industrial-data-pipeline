# Data Model

This document describes the data model used in the Industrial Data Pipeline project.

The model represents a simplified industrial process where operational measurements are collected from reactors, a condenser and a heat exchanger. The generated data is used to monitor process performance, detect abnormal operating conditions and calculate operational KPIs.

---

## Entity Relationship Overview

```text
sensors
   │
   │ 1:N
   ▼
measurements
   │
   │ 1:N
   ▼
alerts
```

---

## Process Overview

The simulated process contains the following operating units:

* Reactor A
* Reactor B
* Steam inlet to condenser
* Condensate outlet from condenser
* Heat exchanger inlet
* Heat exchanger outlet

The dataset includes measurements related to:

* Temperature (°C)
* Pressure (bar)
* Flow rate (m3/h)
* Energy consumption (kWh)

Temperature ranges are defined according to the physical role of each process unit. For example, the heat exchanger outlet operates at higher temperatures than the heat exchanger inlet, while steam entering the condenser operates at higher temperatures than the resulting condensate stream.

## Sensors

Sensor master data.

| Column           | Description                                |
| ---------------- | ------------------------------------------ |
| sensor_id        | Unique sensor identifier                   |
| sensor_name      | Sensor tag                                 |
| production_unit  | Process unit where the sensor is installed |
| variable_type    | Measured variable                          |
| engineering_unit | Measurement unit                           |
| min_limit        | Lower operating limit                      |
| max_limit        | Upper operating limit                      |

Examples:

* TEMP_REACTOR_A
* PRESS_REACTOR_B
* FLOW_STEAM_CONDENSER_IN
* TEMP_HEAT_EXCHANGER_OUT

---

## Measurements

Time-series measurements generated by sensors.

Each record represents one measurement collected from a sensor at a specific point in time.

| Column         | Description                           |
| -------------- | ------------------------------------- |
| measurement_id | Unique measurement identifier         |
| sensor_id      | Sensor that generated the measurement |
| timestamp      | Date and time of the measurement      |
| value          | Recorded measurement value            |

The dataset contains one year of hourly measurements for all sensors.

---

## Alerts

Operational alerts generated when measurements exceed predefined operating limits.

Each alert is associated with a measurement that falls below the minimum limit or exceeds the maximum limit configured for the corresponding sensor.

| Column         | Description                          |
| -------------- | ------------------------------------ |
| alert_id       | Unique alert identifier              |
| measurement_id | Measurement that triggered the alert |
| alert_type     | Type of alert generated              |
| severity       | Alert severity level                 |
| created_at     | Alert creation timestamp             |

---

## Design Notes

The model separates sensor metadata from measurement records. This avoids repeating sensor information in every measurement and improves maintainability.

The alerts table is derived from measurements and enables abnormal operating conditions to be analysed independently from normal operating behaviour.

The objective of the model is not to reproduce a complete process simulation, but to provide a realistic industrial dataset suitable for ETL development, data quality validation and KPI generation.
